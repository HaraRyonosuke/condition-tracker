# ADR-006: データの保存と持ち出し

## ステータス

accepted

## コンテキスト

US-01 で記録を残す必要がある。現行の React ツールはアプリ内に履歴を持たず、
整形テキストをクリップボードへコピーし、外部の経過管理スレッドへ貼る運用である。

新しいアプリの当初スコープには一覧（US-02）とグラフ（US-04）も含まれていた。
一方で、常用ブラウザは終了時にサイトデータを消す設定があり、
ブラウザ内保存だけにすると再訪で記録が消える。
共有PCでは認証情報を残したくない（ADR-003）。
公開リポジトリであり、保存先の説明に個人のサービスアカウント名は書かない。

一周目は動く入力を最小で出すことが優先である。
一覧やグラフの正をアプリ内に置くかどうかは、そのストーリーに着手するときに改めて判断する。

制約は以下の通り。

- 一周目は実装と運用の負荷を最小にしたい
- 再起動やブラウザ終了のあと、アプリ内に履歴が残る必要は、一周目では必須ではない
- 常用ブラウザは、終了時にサイトデータを削除する設定がある
- 共有PCに認証やリポジトリを残したくない
- 個人利用であり、運用と費用の負荷は低くしたい
- 現行ツールの主出力は、コピーして外部スレッドへ貼ることである
- 公開リポジトリであり、保存先の説明に個人のサービスアカウント名は書かない

## 選択肢

### 選択肢A: コピーして外部スレッドへ貼ることを主にする

- 長所: 現行運用と一致する。ブラウザのサイトデータ削除の影響を受けない。アプリ側の保存実装が最小
- 短所: 一覧・グラフの正がアプリ外になる。US-02 / US-04 は、保存の正をアプリ側に移すまで着手できない。貼り忘れ・スレッドの散逸で履歴が途切れる

### 選択肢B: ブラウザ内保存（localStorage または IndexedDB）

- 長所: 実装が軽い。外部送信がない。一覧・グラフをアプリ内で完結できる
- 短所: 終了時にサイトデータを消す設定だと残らない。別ブラウザ・別端末では見えない。端末を失うと消える

### 選択肢C: ユーザー操作のファイル書き出し・読み込み

- 長所: 外部送信なし。サイトデータ削除の影響を受けにくい。バックアップを自分で持てる
- 短所: 毎回の書き出しを忘れると消える。一覧のたびに読み込む運用は手間が大きい

### 選択肢D: 外部の DB や BaaS に保存する

- 長所: 端末やブラウザ設定に依存しない。複数環境から同じ履歴を見られる。日付順の一覧に向く
- 短所: 外部送信が発生する。アカウントや費用が乗りやすい。共有PCでのログイン残りが ADR-003 と衝突しうる。要件の「外部送信なし」「認証不要」を見直す必要がある

### 選択肢E: アプリ内保存を正とし、コピー出力は任意の補助にする

- 長所: 一覧・グラフと現行のスレッド運用を両立できる。コピーはバックアップや共有に使える
- 短所: 保存先（B か C か D）を別に決める必要がある。正が二つに見えやすい。サイトデータ削除の問題はアプリ内側に残る

## 決定

一周目の正は、選択肢Aとする。
アプリは記録を永続化せず、整形テキストをクリップボードへコピーする。
履歴の正は、利用者が貼る外部スレッド側にある。

選択肢B（ブラウザ内保存）と選択肢C（ファイルの書き出し・読み込み）は採用せず、将来タスクとする。
選択肢D（外部の DB や BaaS）は一周目では採用しない。日付順の一覧（US-02）に着手するときに、保存手段を再検討する。
選択肢Eは採用しない。正を二つにしない。

## 理由

一周目で効く制約は、最小で入力を始められることと、現行運用を壊さないことである。
選択肢Aは保存実装を持たず、サイトデータ削除にも認証にも触れない。
いまの制約の下では、これが最も合理的である。

一覧をアプリ内で日付順に出すには、ブラウザ終了後も残る正が必要になる。
B は常用ブラウザの削除設定と衝突する。C は残せるが、一覧のたびにファイルを扱う運用が重い。
日付順の一覧に向くのは D だが、外部送信・アカウント・費用・共有PCの認証残りが乗る。
その判断は一覧が必要になった時点（US-02）で足りる。一周目に先回りしない。

E は A と D の両方を同時に抱える。正が二つになり、一周目の最小という制約に合わない。

## 結果

- US-01 の出力はクリップボードへのコピーである。アプリ内に履歴ストアを持たない
- 貼り忘れと、スレッド側の散逸は受け入れる
- ブラウザ内保存（B）とファイル I/O（C）は将来タスクである
- アプリ内保存を正としコピーを補助する形（E）は採らない
- 日付順の一覧（US-02）とグラフ（US-04）は、保存の正をアプリ側に置く判断が終わるまで延期する
- US-02 着手時に保存手段を再検討する。そのときの有力候補は外部 DB / 外部サービス（D）である
- 要件の「外部送信なし」「アプリ内アカウント不要」は一周目では維持する。コピーはアプリが外部へ送る行為ではない
- 共有PCに認証を残さない方針（ADR-003）と衝突しない
- 保存の前提が変わった場合は、本ADRを superseded にして再検討する
