# ADR-012: AI開発支援の使い方と生成コードの扱い

## ステータス

accepted

## コンテキスト

ADR-005 は、開発支援の中心を Cursor にすることと、使い方（判断は自分、Cursor は下書きと論理チェックに限る）を同じ決定に束ねた。
道具の選定は今も実態と合う。一方、実装は Cursor に第一稿を任せる運用へ寄っており、005 の使い方は正として保てなくなった。

上流は Cursor と相談しながら自分主導で、選択肢・制約・決定を `docs/` に残している。
下流（`src/` と設定）は Cursor 任せになりつつある。これは AI 駆動開発の練習として受け入れている。

生成コードについては、独自性の証明が目的ではない。
他人から「他プロダクトのコードでは」と言われないこと、が本音である。
施設への提供や商用利用は今は二の次であり、全 GitHub との類似度証明や CI のクローン検査は、この段階の負荷に見合わない。

制約は以下の通り。

- 主目的は、設計判断を自分の言葉で残すことと、AI 駆動開発の練習である
- 施設提供・商用は今は二の次である
- 上流の判断（選択肢・制約・決定）は自分主導のままにする
- 下流の第一稿は Cursor に書いてよい
- 生成コードは、メジャーな他プロダクトの実装を `src/` に持ち込まない
- Vue / Pinia / Vite は依存として使う。公式の使い方に似ることは問題にしない
- 独自であることの証明は求めない
- 個人プロジェクトであり、検査の道具は増やしすぎない
- 公開リポジトリであり、文書に個人的・医療的な記述は含めない

## 選択肢

### 選択肢A: ADR-005 の使い方を維持する

判断も実装の下書きも 005 どおりに戻す。生成物の確認は薄くてよい。

- 長所: 文書と運用が再び一致する。生成の先行を抑える
- 短所: いまの下流（Cursor に第一稿を任せる練習）と衝突する。守れない約束を残すことになる

### 選択肢B: 設計文面も含めて生成し、承認だけする

上流も Cursor が書き、自分は追認する。

- 長所: 速度は出る
- 短所: 判断を自分の言葉で残すという主目的と衝突する。005 で拒んだ「全部書かせて追認」になる

### 選択肢C: 上流は自分主導、下流は Cursor の第一稿、生成物は持ち込み回避だけ見る

道具は Cursor のまま。上流は相談しつつ自分主導。下流の第一稿は Cursor でよい。
生成物は、入れてないメジャーなライブラリや、知っている他の体調アプリの実装を `src/` に置いていないかを見る。
一字一句の一致や、FW の定型が公式に似ることは見ない。

- 長所: 実態と文書が合う。練習としての委任を認める。他人から言われやすい持ち込みだけに検査を限れる
- 短所: 実装の著者はモデルになる。独自性は証明できない。変数名だけ変えた持ち込みは、機械だけでは取り切れない

### 選択肢D: 類似度スキャンを CI に載せ、独自性を証明する

生成のたびに、有名 OSS との一致を機械で見る。

- 長所: 見た目のゲートが増える
- 短所: 通っても証明にならない。Vue の定型で偽陽性が出る。ADR-010 の「新しいテストの種類は足さない」とも合わない。商用が二の次の今は過剰

## 決定

選択肢Cとする。ADR-005 の道具の決定（Cursor を中心にする。GitHub Copilot は入れない。Claude チャットはリポジトリを触らない壁打ちに限ってよい）は維持する。
使い方と生成コードの扱いについては、本 ADR が正であり、ADR-005 を置き換える。

## 理由

効く制約は、判断は自分の言葉で残すことと、下流を Cursor に任せる練習を続けることである。
選択肢Aは後者を否定する。選択肢Bは前者を否定する。選択肢Dは、今の本音（持ち込みを避ける）より重い証明を求め、練習段階の負荷に見合わない。

生成物を「一致していなければよい」とだけ書くと、FW の定型まで落ち、変数名だけ変えた持ち込みは通る。
見る対象を、依存に入れてないメジャーな実装の再掲と、出典・ライセンス行の混入、知っている他アプリの丸写しに限れば、他人から言われやすい形と検査が揃う。

施設や商用でより強い証明が必要になったときは、本 ADR を superseded にして再検討する。今は練習が先である。

## 結果

- 開発支援の中心は Cursor のままである。Copilot は入れない。Claude チャットはリポジトリを触らない壁打ちに限ってよい
- 上流（要件・ADR・design）は Cursor と相談してよいが、選択肢・制約・決定は自分主導である
- 下流の第一稿は Cursor が書いてよい。005 の「下書きと論理チェックに限る」は捨てる
- 生成コードは独自であることの証明対象ではない。入れてないメジャーな他プロダクトの実装を `src/` に持ち込まない
- Vue / Pinia / Vite の使い方が公式に似ることは問題にしない
- 確認の手順は [docs/README.md](../README.md) の機能スプリント（実装の直後）である。フックと CI はこのために今は足さない
- ADR-005 は本 ADR に置き換える
