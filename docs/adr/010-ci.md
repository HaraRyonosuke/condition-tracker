# ADR-010: PR での自動チェック（CI）

## ステータス

accepted

## コンテキスト

機能スプリントの「テスト」は、手元で `type-check`、lint / format、Vitest を回す（ADR-009）。
PR を出してから merge するまでのあいだ、同じ確認を GitHub 上でも見たい、という必要が出た。
経験は少なく、道具は増やしたくない。

制約は以下の通り。

- 確認する内容は ADR-009 と同じでよい（新しいテストの種類は足さない）
- 個人プロジェクトであり、有料の CI サービスは使わない
- リポジトリは GitHub にある
- husky でコミット前に必ず回す方式は、ADR-008 で今は入れない

## 選択肢

### 選択肢A: 手元だけ（CI なし）

- 長所: 設定ファイルが増えない
- 短所: PR を見る人が、checks が通ったかを GitHub 上で確認できない。押し忘れに気づきにくい

### 選択肢B: GitHub Actions で、手元と同じ npm スクリプトを回す

- 長所: GitHub に付属する。PR に成功／失敗が出る。追加のアカウントが要らない
- 短所: YAML のメンテが少し増える。Windows 手元と Linux ランナーで改行などが違うと format が落ちることがある

### 選択肢C: 別の CI（CircleCI など）

- 長所: 機能は多い
- 短所: アカウントと設定がもう一つになる。この規模では過剰

## 決定

選択肢Bとする。PR と `main` への push で、次を順に回す。

- `npm ci`
- `npm run type-check`
- `npm run lint`
- `npm run format:check`
- `npm run test:unit`

E2E と本番 HTTPS の総合は回さない（ADR-009）。公開先は ADR-011。

## 理由

効く制約は、ADR-009 と同じ確認を、GitHub の PR から見えることである。
選択肢Aは PR の品質ゲートにならない。選択肢Cは手元の GitHub だけで足りる規模に合わない。

## 結果

- 設定は `.github/workflows/ci.yml`
- Node の版は Volta と同じ 26.7.0 を Actions 側でも指定する
- コミット前フック（husky）は、この ADR でも入れない
