# ADR-003: 開発環境の選定

## ステータス

accepted

## コンテキスト

初期セットアップは GitHub Codespaces を前提に進めていた。
常用すると無料枠を超えて課金が発生しうること、また自分専用ではない PC を使う場面があることから、
開発環境を早い段階で決める必要が出てきた。

どこで開発するかを決めないと、セットアップ手順と実際の作業が文書と食い違う。

制約は以下の通り。

- 自分専用ではない共有PCを使う場面がある
- 共有PCには認証情報やリポジトリを残したくない
- 個人の学習用プロジェクトであり、クラウド開発の従量課金は常用したくない
- 小規模な個人プロジェクトであり、環境の二重管理は避けたい
- リポジトリはすでに自前環境へ clone 済みである

## 選択肢

### 選択肢A: GitHub Codespaces で開発する

- 長所: ブラウザだけで環境が揃う。共有PCでもディスクにリポジトリを残さなくてよい。マシン差が小さい
- 短所: 個人アカウントの無料枠（コア時間・ストレージ）に上限がある。枠を超えると課金か停止になる。起動・停止の待ちがある。すでに clone したローカル環境と手順が分かれる

### 選択肢B: 自前PCのローカル環境で開発する

- 長所: 起動が手元で完結し、従量課金がない。共有PCにソースや認証を置かなくてよい
- 短所: Windows 固有のセットアップとトラブル対応を自分で見る。自前PCを持っていけない日は実装できない

### 選択肢C: 共有PCに開発環境を置く

- 長所: 設置されている PC だけで作業できる。持参する荷物が減る
- 短所: 共有端末に Git 認証・依存関係・未コミットの差分が残りうる。セキュリティ上の制約と衝突する。次に使う人との環境差も大きい

### 選択肢D: ローカルと Codespaces を併用する

- 長所: 自前PCがない日の保険になる
- 短所: 手順や Node の版、依存関係、未コミットの扱いが二つに分かれやすい。小規模プロジェクトには運用コストが大きい

## 決定

実装と実行は、自前PCのローカル環境で行う。
共有PCには開発環境を置かない。
共有PCを使う場合は、ブラウザ版の Visual Studio Code（github.dev など）でドキュメントの閲覧・編集にとどめる。
GitHub Codespaces は常用しない。

## 理由

課金を常用したくないことと、共有PCに成果物を残したくないことが同時に効く。
この2つを満たすのは、自分専用の PC でローカル開発することである。

自前PCを持っていけない日に実装できないことは、トレードオフとして受け入れる。
共有PC側で必要な作業はドキュメントのやり取りに限り、github.dev のようなブラウザ上の編集で足りる。
実装・実行環境まで共有PCや Codespaces に広げると、手順が二つになり、認証情報を残すリスクも戻る。

選択肢Aは共有PC対策としては合理的だが、無料枠は常用を想定した量ではなく、
すでに課金の懸念が出ている。学習用の個人プロジェクトで、開発をクラウドに置く理由にならない。

選択肢Cは持参の手間は減るが、共有端末という制約そのものと衝突するため採用しない。

選択肢Dは保険になるが、この規模では手順が分かれるコストの方が大きい。

## 結果

- 開発手順が1系統になる
- Codespaces の従量課金を常用しなくてよい
- 共有PCに認証情報やソースを残さない
- 共有PCでは、ドキュメントの閲覧・編集だけをブラウザ上で行う
- 受け入れた制約として、Windows 上のセットアップは自分で行い、自前PCを持っていけない日は実装しない
- 作業場所の前提が変わった場合は、本ADRを superseded にして再検討する
