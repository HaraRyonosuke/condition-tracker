# ADR-018: 使っているアイコンの読み方

## ステータス

accepted

## コンテキスト

画面のアイコンセットは Lucide である（ADR-016）。いまの読み方は、`@lucide/vue` から、その画面で使っているグリフだけを名前で import する形である。実行時に Lucide のサイトへ取りにいってはいない。文書の説明に置く絵は、画面が読む部品とは別のファイルになっている。

使っている絵をリポジトリ内の一つの置き場に置き、画面と文書の両方をそこから読みたい。

制約は以下の通り。

- セットは Lucide のままである（ADR-016）。他セットと混在させない
- 使っているグリフだけを読む。`icons` 一式は読まない
- ページを開いたときに、絵をネットから取りにいかない
- 画面の絵と、文書が説明する絵は、同じグリフである
- 色は `currentColor` に追従できる。セット固有の塗りを既定にしない

## 選択肢

### 選択肢A: `@lucide/vue` の名前付き import のまま

画面はパッケージの部品を読む。文書用の絵は、必要なら別に置く。

- 長所: ADR-016 の読み方のままである。ビルドが、import したグリフだけを取り込む
- どちらでもない: 実行時のネット取得は、この案でもしていない
- 短所: 画面の部品と、文書の絵ファイルが別物のままである

### 選択肢B: 使っているグリフをリポジトリのファイルにし、画面と文書がそれを読む

正は、使っているグリフの SVG である。置き場は `src/icons/` とする。画面はそこから読む。文書も同じ SVG を参照する。SVG を文書上で直接出せないときは、同じグリフの PNG を `docs/icons/` に置き、正は SVG のままとする。`@lucide/vue` から一式は読まない。

- 長所: 画面と文書が、同じグリフのファイルを指す。実行時にネットへ取りにいかない
- どちらでもない: グリフを足すたびに、ファイルを自分で足す
- 短所: パッケージの部品を直接使う読み方ではなくなる。ADR-016 の「`@lucide/vue` から読む」は、この決定を accepted にしたあとで直す必要がある

## 決定

選択肢Bとする。使っているグリフの正は、リポジトリに置いた SVG である。

## 理由

効く制約は、画面の絵と文書の絵を同じグリフにすることと、実行時にネットから取りにいかないことである。

名前付き import は、画面の中では使っている絵だけを取り込める。一方、文書の絵は別ファイルのまま残り、二つの置き場が並ぶ。

ファイルを正にすると、足す手間は増える。この制約では、置き場が一つであることの方が直接である。セットを Lucide から変える必要はない。

## 結果

- 画面と文書は、`src/icons/` の使っている SVG を読む
- 使っていないグリフのファイルは置かない。一式は読まない
- ページ表示のときに、絵をネットから取りにいかない
- `src/` と `design.md` と ADR-016 の読み方は、この決定のあとで直す

## 確認

accepted にしたあと、画面のビルドに、使っていないグリフが入っていないことと、表示時に Lucide のホストへリクエストが無いことを見る。

## 補足

ADR-016 の読み方の文をこの決定へ合わせる。セット選定の文は残す。実装も、そのあとである。
