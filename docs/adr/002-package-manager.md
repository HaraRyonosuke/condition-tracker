# ADR-002: パッケージマネージャーの選定
 
## ステータス
 
proposed
 
## コンテキスト
 
Vue 3(Vite)のプロジェクト作成時に、npm, pnpm, yarn, bunの4つのパッケージマネージャーが選択肢として提示されている。
今後のライブラリ追加や運用でも継続的につかうものなので、早い段階で選定しておく必要がある。

選定にあたっての制約は以下の通り。
- 自分はnpm, pnpm, yarnを使用した経験があるが、bunを使用した経験がない。
- リハビリ段階の個人プロジェクトであり、ツール自体の学習コストやトラブル対応の負荷は低く抑えたい。
- 将来フリーランスとして現場に入ることを想定しているため、実務での採用率が高いものが望ましい。
- プロジェクト規模が小さいため、インストール速度やディスク効率の差は実質的に影響しない。
 
## 選択肢
 
### 選択肢A: npm
 
- 長所: Node.js同梱で追加インストール不要。Vue公式どっきゅ面との最初の例がnpm。Stack OverflowやGitHub issuesの情報量が最も多い。実務う案件での採用率が高い。
- 短所: 速度はpnpmやbunに劣る。nodemodulesのディスク使用量が大きい。
### 選択肢B: pnpm
 
- 長所: インストール速度が速い。シンボリックリンクベースのnodemodules構造によりディスク効率が良い。採用率が伸びている。
- 短所: node_modulesの構造がnpmと異なるため、まれにライブラリの互換性問題が発生する可能性がある。
### 選択肢C: yarn
 
- 長所: 一時期のデファクトスタンダードであり情報は多い。
- 短所: v1とv2以降で仕様が大きく変わっており、新規プロジェクトで積極的に採用する理由が薄い
### 選択肢D: bun
 
- 長所: 速度が非常に速い。パッケージマネージャーとランタイムが統合されている。
- 短所: Node.js互換性にまだ穴がある場面がある実務案件での採用実績が少ない。使用経験がない。
## 決定
 
npmを採用する。
 
## 理由
 
現時点での制約（リハビリ段階、実務経験がnpm, pnpm, yarn、小規模プロジェクト）を考慮すると、学習コストがゼロで、情報量が最も多く、トラブル時の対応負荷が最も低いnpmが最も合理的な選択である。

pnpmの速度面での優位性は魅力的だが、プロジェクト規模が小さく速度差が体感に影響しないため、現時点では選定理由にならない。将来プロジェクト規模が大きくなった場合やチーム開発で求められた場合に改めて検討する（その際はこのADRをsupersededにして新しいADRを起こす）。
 
## 結果
 
- 追加ツールのインストールなしで開発を開始できる。
- Vue公式ドキュメントのコマンド例をそのまま使える。
- 速度面の最適化は将来課題として許容する。
- package-lock.jsonで依存関係のバージョンが固定される。
