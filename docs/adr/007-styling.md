# ADR-007: スタイリング手段の選定

## ステータス

accepted

## コンテキスト

US-01 で入力画面を実装する。各項目は 4 列の大きいボタンで、スマートフォンの片手操作が主である。
画面は入力 1 枚だけである。履歴は外部スレッドが正であり、一覧やナビは一周目にない（U1）。

イテレーション1はライトテーマのみとする。ダークはイテレーション2（US-03 と同じスプリント）で、
アプリ内切替かブラウザ / OS 同期かを決める。一周目の必須条件にはしない。

スタイルの手段を決めないと、ボタンの大きさ・余白・フォーカスをコンポーネントに埋め込むか、
都度 CSS を書くかがぶれる。入力 UI は見た目と不可分なので、実装の前に決める。

制約は以下の通り。

- 日常の利用者は U1 である。入力 1 画面。大きいタップ領域が必要である
- イテレーション1はライトテーマのみである。ダーク対応は必須ではない
- イテレーション2で同じ画面に行動記録を足し、ダークを足す可能性がある
- Vue 3 + Vite + TypeScript である
- 小規模な個人プロジェクトであり、学習コストと依存の数は低く抑えたい
- 公開リポジトリであり、見た目を盛ることは主目的ではない（読み手は副）
- ダークを後から足せるかは比較の加点であって、一周目の採否条件ではない
- 余白と大きさを自分で揃えたい（既成テーマに寄せない）
- 将来の外部 DB 接続で CRUD 画面が増えても、量は多くない見込みである
- グラフ（US-04）は別 ADR でライブラリを選ぶ。スタイル選定の理由にしない

## 選択肢

### 選択肢A: 素の CSS（単一ファイルまたは Vue の scoped）

- 長所: 依存が増えない。1 画面なら十分な制御ができる。後から捨てやすい
- 短所: 余白・色・ボタン状態を自分で揃える。イテレーション2で項目が増えたときに、規約がないとばらつきやすい。ダークを足すときは変数設計を自分でやる

### 選択肢B: ユーティリティ CSS（Tailwind CSS 単体）

- 長所: クラスで余白と大きさを揃えやすい。独自の 4 択ボタンを既定部品に合わせなくてよい。イテレーション2のフォーム追加でも同じ書き方で足せる。後から `dark` 用クラスや CSS 変数を足しやすい（加点）
- 短所: ツールチェイン（Vite プラグイン等）を覚える。クラスがマークアップに乗る。CRUD 用の既成フォーム部品はない

### 選択肢B': ユーティリティ CSS + 意味クラス（例: Tailwind CSS + daisyUI）

- 長所: 標準ボタンやカードは速い。テーマ切替が後から楽になりやすい
- 短所: 独自 4 択ではクラスの上書きが増える。見た目がテーマに寄りやすい。依存が一本増える

### 選択肢C: Vue 向けコンポーネントライブラリ（例: Vuetify, Element Plus, Naive UI）

- 長所: ボタン・フォーム・テーブルが揃っている。CRUD が多い画面では実装が速い。ダークテーマを後から足しやすい製品が多い
- 短所: 1 画面・大きい独自 4 択には過剰。見た目がライブラリの既定に寄る。学習とバンドルが増える。グラフ描画そのものは別ライブラリであり、C を選ぶ理由にはならない

## 決定

スタイリングは Tailwind CSS 単体とする（選択肢B）。
daisyUI などの意味クラス層は載せない。
Vue 向けコンポーネントライブラリは採用しない。

## 理由

効く制約は、入力 1 画面の独自 4 択を自分で組みたいことと、依存を増やしすぎないことである。
余白と大きさをユーティリティで置くなら、選択肢Bが最も直接である。

選択肢Aは依存は増えないが、イテレーション2で項目とダークを足すときの揃えが弱い。
ユーティリティの段階（余白・幅・文字サイズ）を先に持つ方が、この制約では合理的である。

選択肢B'は現場の速さとテーマ切替では有利だが、既成の `btn` に寄せると独自 4 択と衝突しやすい。
速さより見た目の制御を取るため、採用しない。

選択肢Cの部品の多さは、CRUD が主戦場のときに効く。
外部 DB を将来足しても画面量は多くない見込みなので、一周目に C を載せる理由にならない。
グラフは Chart.js や ECharts など別 ADR の対象であり、Vuetify 等を先に入れる根拠にはならない。

実務で CRUD 中心の現場に入ったときは、その現場の庫に合わせる。
このリポジトリの正は、入力 UI を自分で組む練習として B に置く。

## 結果

- US-01 の見た目は Tailwind CSS のユーティリティで組む
- イテレーション1ではダークを実装しない
- daisyUI などの意味クラス層は載せない
- Vuetify 等のコンポーネント庫は採用しない。CRUD が増えて方針が変わったら、本ADRを superseded にして再検討する
- グラフ用ライブラリは US-04 着手時の別 ADR とする
- イテレーション2のダーク（切替かブラウザ同期か）は、この ADR では決めない。Tailwind の `dark` や CSS 変数で足せる前提を残す
