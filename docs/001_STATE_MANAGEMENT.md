# ADR-001: 状態管理ライブラリの選定
 
## ステータス
 
accepted
 
## コンテキスト
 
体調記録アプリでは、入力フォームの状態・記録データの一覧・グラフ表示用のデータなど、
複数のコンポーネント間で状態を共有する必要がある。
 
Vue 3のComposition APIだけで管理することも可能だが、
アプリの規模が小さいとはいえ、状態管理の設計判断を明示的に行い記録することが
このプロジェクトの学習目的に含まれる。
 
制約として、自分のVue 3実務経験ではVuexを使ったことはあるが、
Piniaは公式ドキュメントを読んだ程度であること。
 
## 選択肢
 
### 選択肢A: Pinia
 
- 長所: Vue 3公式推奨。TypeScriptとの親和性が高い。Vuexより軽量でAPIがシンプル
- 短所: 実務での使用経験がない
### 選択肢B: Vuex 4
 
- 長所: 使用経験がある。情報が多い
- 短所: Vue 3ではPiniaが公式推奨に変わっており、新規プロジェクトでの採用は減少傾向
### 選択肢C: Composition API（provide/inject）のみ
 
- 長所: 追加ライブラリ不要。小規模アプリには十分
- 短所: 設計判断が暗黙的になりやすく、学習目的に合わない
## 決定
 
Piniaを採用する。
 
## 理由
 
このプロジェクトの目的は動くアプリを作ることだけでなく、
上流設計の判断プロセスを練習することにある。
Piniaは現在のVueエコシステムの標準であり、
今後のフリーランス案件でも求められる可能性が高い。
 
実務経験がない点はリスクだが、アプリの規模が小さいため
学習コストが過大になる可能性は低いと判断した。
 
## 結果
 
- Piniaの学習コストを受け入れる（公式ドキュメントの通読が必要）
- ストアの設計がポートフォリオとして見せられる成果物になる
- Vuexの経験は活かしつつ、新しいAPIに慣れる機会になる
