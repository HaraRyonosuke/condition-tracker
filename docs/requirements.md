# 課題定義・要件

## 1. 課題の背景

体調のセルフモニタリングを日常的に行う場合、記録手段が手書きのノートや
汎用のテキストメモに分散しやすく、以下の問題が生じる。

- 蓄積したデータを日付順に振り返ることが難しい
- 数値の推移や傾向を視覚的に把握できない
- 記録項目が固定されないため、日によって記録内容にばらつきが出る

本プロジェクトでは、定型化された入力フォームにより記録項目を固定し、
整形テキストとして外部の経過管理スレッドへ持ち出せるようにする。
蓄積の振り返りは、当面そのスレッド側で行う。

## 2. 想定ユーザ

役割は混ぜない。決めるのは日常の利用者の主だけである。

| 役割               | 主/副 | 内容                                                                                         |
| ------------------ | ----- | -------------------------------------------------------------------------------------------- |
| 日常の利用者（U1） | 主    | スコアを入力し、整形テキストをコピーする。履歴の正は外部スレッド。アプリを開くのは入力のとき |
| リポジトリの読み手 | 副    | ADR と実装を追う（学習・判断の記録）。見た目を盛る理由にはしない                             |

対象外: 不特定多数向けのプロダクト化、複数ユーザー。

U2（このアプリで経過も見たい記録者）は主にしない。アプリ内一覧・グラフは、保存の正をアプリ側に置く判断のあとの将来とする。

## 3. スコープ

### いま解くこと（イテレーション1）

- 定型項目による体調スコア（7項目 / 各0〜3点 / 合計0〜21点）の入力
- 整形テキストのクリップボードへのコピー（履歴の正は外部スレッド。ADR-006）
- Tailwind CSS による入力画面のスタイル（ライトテーマ。ADR-007）

### イテレーション2で解くこと

- 行動記録（入浴・食事・外出）を入力し、コピー文面へ足す（US-03）
- ダークテーマ（アプリ内切替か、ブラウザ / OS 同期かはそのとき決める）

### 保存の正をアプリ側に移すときに解くこと

- ログイン（US-06）。個人の記録に紐づける。複数ユーザーやデータ共有は対象外のまま
- 外部サービス連携（US-07）。保存先やスレッド以外への送信。連携先は保存の再検討と合わせて決める
- 記録の一覧表示（日付降順）。保存手段の再検討が先（外部 DB / 外部サービスが有力。US-02）
- スコア推移のグラフ表示（一覧と同じ保存の正が前提。US-04）

### コピー文面の拡張として、イテレーション2より後でも解けること

- 自由記述のメモ（US-05）

### 構想（ストーリーだけ置く。ADR は着手時）

静的な入力1画面から先の形。ADR は今は書かない。ホスト・ルーティング・アプリ配布の番号も予約しない。

- 静的配布から動的なアプリへ（US-08）
- ダッシュボードで概況を見る（US-09）
- ダッシュボードのパネルから各画面へ移る（US-10）
- ブラウザ以外のアプリ版（US-11）。PWA / ネイティブ / ラッパーかは当時決める

### 解かないこと（将来タスク）

棚卸しの結果を、ここに集約する。採用しないものではなく、着手しないもの。

**保存・持ち出し（ADR-006 で一周目は不採用。イテレーション2でも開かない）**

- ブラウザ内保存（localStorage / IndexedDB）
- ユーザー操作のファイル書き出し・読み込み
- アプリ内保存を正とし、コピーを補助にする形
- 外部 DB / BaaS（US-02 / US-07 着手時に再検討）

**入力の拡張（現行ツール寄せ。一周目では持たない）**

- 入浴・外出を開始・終了の時間幅で持つ
- 設定で bool と時間入力を切り替える汎用化
- 食事を回数ではなく朝昼晩・間食の時刻で持つ（US-03 着手時に寄せ方を決める）
- 活動の開始・終了・内容の行追加
- 「今日のこと」「相談・共有」の 2 メモに分けるか（US-05 着手時に決める）
- 合計の帯ラベル（低 / 軽度 / 中等度 / 要注意）。診断に読まれやすい
- タイムライン、空き時間、時刻ピッカーの作り込み

**テーマ**

- イテレーション1のダークモード（`prefers-color-scheme` も専用切替も入れない）

**プロダクトとして今は対象外**

- 複数ユーザー対応・データ共有（個人のログイン US-06 とは別）
- 気象データなど、記録以外の外部API（US-07 の連携先を決めるまで持たない）
- 動的ホスト・サーバー（US-08。一周目は GitHub Pages の静的配布。ADR-011）
- ダッシュボードと画面遷移（US-09 / US-10。一周目は入力1画面。Router なし）
- アプリ版（US-11）
- レポート出力機能
- 通知・リマインド機能
- チェック項目定義の英語名

## 4. ユーザーストーリー

| ID    | 優先度 | ストーリー                                                                                                                                                                                          |
| ----- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| US-01 | 高     | 利用者として、その日の体調を7項目のスコアで入力し、整形テキストをコピーしたい。なぜなら、記録を習慣化するために入力の手間を最小限にしたいから。                                                     |
| US-03 | 高     | 利用者として、行動記録（入浴・食事・外出）も合わせて入力したい。なぜなら、行動と体調の関連を後からスレッドで確認したいから。                                                                        |
| US-05 | 低     | 利用者として、記録に自由記述のメモを残したい。なぜなら、定型項目では表現できない事柄を補足したいから。                                                                                              |
| US-02 | 低     | 利用者として、過去の記録を日付順に一覧で確認したい。なぜなら、記録の蓄積を振り返りたいから。履歴の正は当面スレッド側。アプリ内一覧にするなら保存手段の再検討が先である。                            |
| US-04 | 低     | 利用者として、スコアの推移をグラフで確認したい。なぜなら、数値の羅列より視覚的な方が傾向を掴みやすいから。保存の正がアプリ側になってから着手する。                                                  |
| US-06 | 低     | 利用者として、自分のアカウントでログインしたい。なぜなら、記録をアプリや外部の保存先に残すときに、端末をまたいでも自分の分だけ見たいから。方式と共有PC方針（ADR-003）は着手時に決める。             |
| US-07 | 低     | 利用者として、記録を外部サービスへ連携したい。なぜなら、クリップボード経由の貼り付け以外でも経過を残したり、保存の正をアプリ外に置きたいから。連携先は US-02 の保存再検討と合わせて決める。         |
| US-08 | 低     | 利用者として、静的なページではなく動的なアプリとして使いたい。なぜなら、ログインや保存、ダッシュボードのようにサーバー側の状態が要る機能を足していきたいから。ホストや構成は着手時の ADR で決める。 |
| US-09 | 低     | 利用者として、ダッシュボードで記録の概況を見たい。なぜなら、入力画面だけでなく、蓄積を一つの画面で把握したいから。一覧（US-02）やグラフ（US-04）との切り分けは着手時に決める。                      |
| US-10 | 低     | 利用者として、ダッシュボードのパネルから各画面へ移りたい。なぜなら、概況から入力・一覧・グラフなど必要な操作へすぐ行きたいから。ルーティングの手段は着手時の ADR で決める。                         |
| US-11 | 低     | 利用者として、ブラウザ以外のアプリ版でも使いたい。なぜなら、日常の入力をホーム画面やストアのアプリから開きたいから。PWA / ネイティブ / ラッパーかは着手時に決める。                                 |

### イテレーション計画

グラフライブラリの ADR 番号は予約しない。US-04 に着手するまで、先に書く ADR があれば番号はそちらが取る。
動的化・ダッシュボード・アプリ版の ADR も予約しない（US-08〜11）。
スタイルは Tailwind CSS 単体とする（ADR-007）。一周目はライトテーマのみ。
各イテレーション（スプリント）は、機能スプリントとリリーススプリントに分け、サイクル末尾で振り返りと引き継ぎを行う（[docs/README.md](./README.md) の「スプリントの進め方」）。
テストは薄い単体（Vitest）と本番 URL での人手の総合とする（ADR-009）。2周目以降のリリースは短い再デプロイ。ダークはイテレーション2着手時に決める。

| イテレーション | 対象                                                                        | ブランチ                    |
| -------------- | --------------------------------------------------------------------------- | --------------------------- |
| 1              | 初期セットアップ + US-01（入力とコピー）+ Tailwind CSS（ライトのみ）        | `feature/us-01-score-input` |
| 2              | US-03（行動記録をコピー文面へ）+ ダーク（切替かブラウザ同期かは当時決める） | （着手時に切る）            |

US-05、アプリ内一覧（US-02）、グラフ（US-04）、ログイン（US-06）、外部連携（US-07）、動的化（US-08）、ダッシュボード（US-09 / US-10）、アプリ版（US-11）はイテレーション2に含めない。これらの ADR 番号は予約しない。

## 5. 非機能要件

| 項目           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 対象デバイス   | 一周目はブラウザ。スマートフォン（主）、PC（副）。アプリ版は US-11                                       |
| データ保存     | アプリ内に永続化しない。クリップボードへコピーし、履歴の正は外部スレッド（ADR-006）                      |
| 外部送信       | 一周目はアプリが記録を外部へ送らない。貼り付けは利用者の操作。US-07 着手時に見直す                       |
| 認証           | 一周目はアプリ内アカウント不要（ADR-006）。ログインは US-06。外部保存を選ぶ場合は US-02 と合わせて見直す |
| パフォーマンス | 特段の要件なし（想定データ量が小規模のため）                                                             |
| UI             | イテレーション1はライトテーマのみ。ダークはイテレーション2で、アプリ内切替かブラウザ / OS 同期かを決める |
| 入力操作       | スマートフォンでの片手操作を想定                                                                         |
| テスト         | 単体は Vitest（薄く）。総合は本番 HTTPS での人手確認。E2E 自動は置かない（ADR-009）                      |
| 公開面         | 一周目は静的な GitHub Pages（ADR-011）。確認は利用者が触る本番 URL。動的化は US-08。ホストの ADR は当時  |

## 6. 用語定義

| 用語               | 定義                                                                                             |
| ------------------ | ------------------------------------------------------------------------------------------------ |
| 日常の利用者（U1） | スコアを入力しコピーする人。履歴は外部スレッドで見る                                             |
| 体調スコア         | 7つのチェック項目の合計点（0〜21）。数値が高いほど、質問への当てはまり（自覚している負担）が強い |
| チェック項目       | 体調を構成する7つの評価軸。各項目は0〜3点。0はなし、3はとても当てはまる                          |
| 行動記録           | 入浴・食事回数・外出の有無など、体調スコア以外の日常行動の記録                                   |
| 記録日時           | 記録した瞬間。タイムゾーン付き。1日に複数件あってよい                                            |
| 記録日             | 記録日時をブラウザのタイムゾーンで解釈した暦日。一覧のグループ用（一覧は保存再検討後）           |
| コピー出力         | 入力内容から作る整形テキスト。クリップボードへコピーし、外部スレッドへ貼る                       |
| ダッシュボード     | 記録の概況をまとめて見る画面。パネルから入力・一覧・グラフなどへ移る（US-09 / US-10。構想）      |
