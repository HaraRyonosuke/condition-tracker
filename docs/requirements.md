# 課題定義・要件
 
## 1. 課題の背景
 
体調のセルフモニタリングを日常的に行う場合、記録手段が手書きのノートや
汎用のテキストメモに分散しやすく、以下の問題が生じる。
 
- 蓄積したデータを日付順に振り返ることが難しい
- 数値の推移や傾向を視覚的に把握できない
- 記録項目が固定されないため、日によって記録内容にばらつきが出る
本プロジェクトでは、定型化された入力フォームと蓄積データの可視化により、
記録の継続性と振り返りやすさを両立することを目指す。
 
## 2. スコープ
 
### 解くこと
 
- 定型項目による体調スコア（7項目 / 各0〜3点 / 合計0〜21点）の入力
- 記録の一覧表示（日付降順）
- スコア推移のグラフ表示
- 行動記録（入浴・食事回数・外出）の併記
### 解かないこと（将来の拡張候補）
 
- 複数ユーザー対応・データ共有
- 外部サービス連携（気象データ等）
- レポート出力機能
- 通知・リマインド機能
## 3. ユーザーストーリー
 
| ID | 優先度 | ストーリー |
|----|--------|-----------|
| US-01 | 高 | 利用者として、その日の体調を7項目のスコアで入力したい。なぜなら、記録を習慣化するために入力の手間を最小限にしたいから。 |
| US-02 | 高 | 利用者として、過去の記録を日付順に一覧で確認したい。なぜなら、記録の蓄積を振り返りたいから。 |
| US-03 | 中 | 利用者として、行動記録（入浴・食事・外出）も合わせて入力したい。なぜなら、行動と体調の関連を後から確認したいから。 |
| US-04 | 中 | 利用者として、スコアの推移をグラフで確認したい。なぜなら、数値の羅列より視覚的な方が傾向を掴みやすいから。 |
| US-05 | 低 | 利用者として、記録に自由記述のメモを残したい。なぜなら、定型項目では表現できない事柄を補足したいから。 |

## 4. 非機能要件
 
| 項目 | 内容 |
|------|------|
| 対象デバイス | スマートフォン（主）、PC（副） |
| データ保存 | ローカル保存（外部送信なし） |
| 認証 | 個人利用のため不要 |
| パフォーマンス | 特段の要件なし（想定データ量が小規模のため） |
| UI | 夜間の使用を想定し、ダークモード対応が望ましい |
| 入力操作 | スマートフォンでの片手操作を想定 |
 
## 5. 用語定義
 
| 用語 | 定義 |
|------|------|
| 体調スコア | 7つのチェック項目の合計点（0〜21）。数値が高いほど状態が良い |
| チェック項目 | 体調を構成する7つの評価軸。各項目は0〜3点で評価する |
| 行動記録 | 入浴・食事回数・外出の有無など、体調スコア以外の日常行動の記録 |
| 記録日 | 記録の対象となる日付。1日1件を原則とする |
