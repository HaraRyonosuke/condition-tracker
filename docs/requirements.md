# 課題定義・要件

## 1. 課題の背景

体調のセルフモニタリングを日常的に行う場合、記録手段が手書きのノートや
汎用のテキストメモに分散しやすく、以下の問題が生じる。

- 蓄積したデータを日付順に振り返ることが難しい
- 数値の推移や傾向を視覚的に把握できない
- 記録項目が固定されないため、日によって記録内容にばらつきが出る

本プロジェクトでは、定型化された入力フォームにより記録項目を固定し、
整形テキストとして外部の経過管理スレッドへ持ち出せるようにする。
蓄積の振り返りは、当面そのスレッド側で行う。

## 2. 想定ユーザ

役割は混ぜない。決めるのは日常の利用者の主だけである。

| 役割 | 主/副 | 内容 |
|------|-------|------|
| 日常の利用者（U1） | 主 | スコアを入力し、整形テキストをコピーする。履歴の正は外部スレッド。アプリを開くのは入力のとき |
| リポジトリの読み手 | 副 | ADR と実装を追う（学習・判断の記録）。見た目を盛る理由にはしない |

対象外: 不特定多数向けのプロダクト化、複数ユーザー。

U2（このアプリで経過も見たい記録者）は主にしない。アプリ内一覧・グラフは、保存の正をアプリ側に置く判断のあとの将来とする。

## 3. スコープ

### いま解くこと（イテレーション1）

- 定型項目による体調スコア（7項目 / 各0〜3点 / 合計0〜21点）の入力
- 整形テキストのクリップボードへのコピー（履歴の正は外部スレッド。ADR-006）
- Tailwind CSS による入力画面のスタイル（ライトテーマ。ADR-007）

### イテレーション2で解くこと

- 行動記録（入浴・食事・外出）を入力し、コピー文面へ足す（US-03）
- ダークテーマ（アプリ内切替か、ブラウザ / OS 同期かはそのとき決める）

### 保存の正をアプリ側に移したあとで解くこと

- 記録の一覧表示（日付降順）。保存手段の再検討が先（外部 DB / 外部サービスが有力）
- スコア推移のグラフ表示（一覧と同じ保存の正が前提）

### コピー文面の拡張として、イテレーション2より後でも解けること

- 自由記述のメモ（US-05）

### 解かないこと（将来タスク）

棚卸しの結果を、ここに集約する。採用しないものではなく、着手しないもの。

**保存・持ち出し（ADR-006 で一周目は不採用。イテレーション2でも開かない）**

- ブラウザ内保存（localStorage / IndexedDB）
- ユーザー操作のファイル書き出し・読み込み
- アプリ内保存を正とし、コピーを補助にする形
- 外部 DB / BaaS（US-02 をアプリ内一覧としてやるときに再検討）

**入力の拡張（現行ツール寄せ。一周目では持たない）**

- 入浴・外出を開始・終了の時間幅で持つ
- 設定で bool と時間入力を切り替える汎用化
- 食事を回数ではなく朝昼晩・間食の時刻で持つ（US-03 着手時に寄せ方を決める）
- 活動の開始・終了・内容の行追加
- 「今日のこと」「相談・共有」の 2 メモに分けるか（US-05 着手時に決める）
- 合計の帯ラベル（低 / 軽度 / 中等度 / 要注意）。診断に読まれやすい
- タイムライン、空き時間、時刻ピッカーの作り込み

**テーマ**

- イテレーション1のダークモード（`prefers-color-scheme` も専用切替も入れない）

**プロダクトとして今は対象外**

- 複数ユーザー対応・データ共有
- 外部サービス連携（気象データ等）
- レポート出力機能
- 通知・リマインド機能
- チェック項目定義の英語名

## 4. ユーザーストーリー

| ID | 優先度 | ストーリー |
|----|--------|-----------|
| US-01 | 高 | 利用者として、その日の体調を7項目のスコアで入力し、整形テキストをコピーしたい。なぜなら、記録を習慣化するために入力の手間を最小限にしたいから。 |
| US-03 | 高 | 利用者として、行動記録（入浴・食事・外出）も合わせて入力したい。なぜなら、行動と体調の関連を後からスレッドで確認したいから。 |
| US-05 | 低 | 利用者として、記録に自由記述のメモを残したい。なぜなら、定型項目では表現できない事柄を補足したいから。 |
| US-02 | 低 | 利用者として、過去の記録を日付順に一覧で確認したい。なぜなら、記録の蓄積を振り返りたいから。履歴の正は当面スレッド側。アプリ内一覧にするなら保存手段の再検討が先である。 |
| US-04 | 低 | 利用者として、スコアの推移をグラフで確認したい。なぜなら、数値の羅列より視覚的な方が傾向を掴みやすいから。保存の正がアプリ側になってから着手する。 |

### イテレーション計画

グラフライブラリの ADR 番号は予約しない。US-04 に着手するまで、先に書く ADR があれば番号はそちらが取る。
スタイルは Tailwind CSS 単体とする（ADR-007）。一周目はライトテーマのみ。

| イテレーション | 対象 | ブランチ |
|---------------|------|---------|
| 1 | 初期セットアップ + US-01（入力とコピー）+ Tailwind CSS（ライトのみ） | `feature/us-01-score-input` |
| 2 | US-03（行動記録をコピー文面へ）+ ダーク（切替かブラウザ同期かは当時決める） | （着手時に切る） |

US-05、アプリ内一覧（US-02）とグラフ（US-04）はイテレーション2に含めない。

## 5. 非機能要件

| 項目 | 内容 |
|------|------|
| 対象デバイス | スマートフォン（主）、PC（副） |
| データ保存 | アプリ内に永続化しない。クリップボードへコピーし、履歴の正は外部スレッド（ADR-006） |
| 外部送信 | アプリは記録を外部へ送らない。貼り付けは利用者の操作である |
| 認証 | 個人利用のため、アプリ内アカウントは不要。外部保存を選ぶ場合は US-02 着手時に見直す |
| パフォーマンス | 特段の要件なし（想定データ量が小規模のため） |
| UI | イテレーション1はライトテーマのみ。ダークはイテレーション2で、アプリ内切替かブラウザ / OS 同期かを決める |
| 入力操作 | スマートフォンでの片手操作を想定 |

## 6. 用語定義

| 用語 | 定義 |
|------|------|
| 日常の利用者（U1） | スコアを入力しコピーする人。履歴は外部スレッドで見る |
| 体調スコア | 7つのチェック項目の合計点（0〜21）。数値が高いほど、質問への当てはまり（自覚している負担）が強い |
| チェック項目 | 体調を構成する7つの評価軸。各項目は0〜3点。0はなし、3はとても当てはまる |
| 行動記録 | 入浴・食事回数・外出の有無など、体調スコア以外の日常行動の記録 |
| 記録日時 | 記録した瞬間。タイムゾーン付き。1日に複数件あってよい |
| 記録日 | 記録日時をブラウザのタイムゾーンで解釈した暦日。一覧のグループ用（一覧は保存再検討後） |
| コピー出力 | 入力内容から作る整形テキスト。クリップボードへコピーし、外部スレッドへ貼る |
