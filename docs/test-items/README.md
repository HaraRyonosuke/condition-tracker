# Product Test

本番 URL で人が見る項目を、リリースごとに残す。1項目ごとに、テスト内容と、テスト日・環境・結果・確認者を書く。

## 名前

- フォルダ名は、リリースノートのファイル名から拡張子を除いたものにする。機能リリースは `US-03`。項目が変わる再デプロイは `redeploy-2026-08-25`
- ファイル名は `product-test.md` にする

## 項目

```markdown
## （項目の名前）

テスト内容: （何を見たか）

| テスト日   | 環境         | 結果                              | 確認者         |
| ---------- | ------------ | --------------------------------- | -------------- |
| YYYY-MM-DD | （ブラウザ） | 通った / 失敗 / 未実施 / 問題なし | （誰が見たか） |
```

同じ項目を別の日や別の環境で見たときは、行を足す。見ていない環境の行は作らない。見たうえでその中身まで見ていなければ、結果は未実施にする。

## 引き継ぎ

新しく Product Test をするときは、直近の `product-test.md` を新しいフォルダへコピーし、そのコピーに項目を足す、または直す。空の一覧から始めない。コピーした項目のテスト内容と、それまでの結果の行は残す。そのリリースで見た行を表に足す。

項目が変わらない再デプロイは、フォルダを増やさない。見る項目は直近の `product-test.md` のまま、そのファイルの表に行を足す。

いまの直近は [US-03/product-test.md](./US-03/product-test.md) である。US-01 のフォルダは無い。US-01 の項目は、この初版に含めてある。
