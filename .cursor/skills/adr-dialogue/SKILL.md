# ADR を対話で作る

ADR の選択肢・制約・決定は、本人の言葉で残す（[ADR-012](../../../docs/adr/012-ai-usage-and-generated-code.md)）。このskillは、そのための問いの順と書き方を決める。手順を決めた判断は [ADR-019](../../../docs/adr/019-adr-dialogue.md) である。

| 何を                                | 正                                                   |
| ----------------------------------- | ---------------------------------------------------- |
| いつ ADR を切るか、番号、ステータス | [adr-proposal](../../rules/adr-proposal.mdc)         |
| 見出しの型                          | [000-template.md](../../../docs/adr/000-template.md) |
| どう対話して下書きを作るか          | このskill                                            |

## 進め方の決まり

- 問いは1つずつ出す。答えを待ってから次へ進む
- 書くのは本人の答えだけである。文末と誤字を整えるのはよい。意味を足さない。言い換えない
- 見出しを1つ書いたら、書いた文を見せて確かめる。確かめが取れてから次の見出しへ進む。なぜ：最後にまとめて書くと、Cursor が全体を自分の言葉で書き直しやすいためである
- コミットはしない。頼まれたときだけする（adr-proposal）

## 問いの順

1. **傾き**：「もう傾いている案はありますか」と聞く。答えは控えておき、ファイルには書かない。なぜ：選択肢の段で、傾いた案と比べられる相手を足すためである
2. **背景**：なぜこの判断が要るのかを聞く。聞き終えたら、タイトル（何についての判断か）を本人と決める。ここでファイルを作る。番号の取り方は adr-proposal に従い、ステータスは `proposed` にする
3. **制約**：判断に効く条件を聞く
4. **選択肢**：本人に、出し切るまで聞く（「ほかにありますか」）。各選択肢の長所・どちらでもない・短所も本人に聞く
5. **選択肢を足す**：本人が出し切ったあとで、抜けている選択肢があれば Cursor が提案する。傾いた案に対抗できるものを先に考える。提案には、どこから持ってきたかを添える。長所と短所の案も一緒に示し、本人に直してもらう。採るかどうかは本人が決める。採ったものは、見出しに `（Cursor が提案。出典: …）` と書く。なぜ：あとから、どの選択肢が本人のものかを見分けるためである
6. **決定**：どれを選ぶかを本人に聞く。Cursor から決定案を出さない
7. **理由**：どの制約が効いたかを聞く。選ばなかった選択肢が、どの制約を満たさないかも聞く
8. **結果**：得るものと、受け入れる制約の両方を聞く
9. **確認・補足**：「あれば」と聞く。無ければ見出しは空のままでよいか確かめる

## 終わり方

- 全部の見出しを確かめたら、ステータスは `proposed` のままにする。`accepted` にするのは、本人が受け入れたときである（adr-proposal）
- 途中でやめたときは、`proposed` のまま残す。消すかどうかは本人が決める

## 決めてはいけないこと

- 決定案を出すこと
- 本人が出す前に、選択肢を出すこと
- 本人の答えを言い換えること、意味を足すこと
- 確かめが取れていない見出しを書くこと
- `accepted` にすること

```
# ❌ BAD
最初に選択肢と決定案を並べて選ばせる / 対話が終わってから全体を書き直す / Cursor が足した選択肢を本人のものと同じに書く

# ✅ GOOD
傾きを控える → 背景を聞いてファイルを作る → 見出しごとに聞いて、書いて、確かめる → 本人が出し切ってから選択肢を足す → 決定は本人に聞く → proposed のまま渡す
```

禁止: Cursor から決定案を出すこと。確かめていない文をファイルに書くこと。

## ほかとの境界

- いつ ADR を切るか、切らないか、番号、テンプレート、ステータスの移し方は [adr-proposal](../../rules/adr-proposal.mdc) である。このskillには書かない
- 判断が変わって古い ADR を `superseded` にする手順は [docs/README.md](../../../docs/README.md) の「ドキュメントの書き進め方」である
